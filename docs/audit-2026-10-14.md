# Source and offline audit — October 14, 2026

This audit covers the current CLI, TUI, configuration, protocol policy and Linux /
Windows backend source. It is not native Windows runtime or advanced protocol
verification. See the [progress checklist](implementation-progress.md) for the
remaining hardware and release requirements.

## Shared authorization and operation flow

The CLI and native TUI use `application` for canonical setting validation, exact
model/firmware permission checks and readable-field preflight. Public mutable
`Setting` fields cannot substitute a different instruction or payload. Profiles
validate every requested field before the first write; individual operations
repeat firmware/preflight checks. Writes remain sequential, with no automatic
retry or rollback. The low-level raw request API remains caller-managed.

The feature registry supplies operation capability checks and the command registry
supplies JSON support to parsing and help. Status JSON identifies a model as
user-selected, rather than detected. Both audio inventory aliases produce the same
versioned JSON shape independently of UI language. Multipoint refresh reads core
status; neither host pairing nor dual mode invents peer identities.

## Connection lifecycle and interface state

Linux host signals invalidate an independently observed host snapshot. Reads,
message sizes, cancellation, refresh frequency and reconnect backoff are bounded.
Partial/coalesced messages and stop/drop behavior have offline coverage. A live
system-bus test accepted all subscriptions for the connected target; receiving a
physical state transition remains unverified.

Definitive RFCOMM IO failures close the session, while a timeout does not silently
reconnect or replay a write. Explicit reconnect preserves uncertain-write lockout;
a completed explicit refresh is required to clear it. Request identifiers and
address matching reject stale results after target changes. Windows-specific
source compiles, but its actual Bluetooth, audio and terminal lifecycle still
requires a native Windows trial.

Navigation, modal guards, narrow/wide layout, all-locale rendering and offline PTY
shutdown tests cover the TUI. Shortcut hitboxes use terminal cell widths. Spatial
writes use readback wording without claiming a nonexistent acknowledgment.
Finder forms accept bounded host output identifiers instead of MAC-only input;
this correction grants no finder capability.

## Configuration, profiles and catalogs

Registry loading bounds input before parsing, ignores unknown sections, sanitizes
names and preserves supported migration forms. Atomic sibling-file replacement
has concurrent-save coverage. Injected path tests cover Windows APPDATA / USERPROFILE
and Linux XDG / HOME selection, plus explicit `UGREEN_STATE_FILE` override.

Profiles round-trip in all eleven languages and reject duplicate or wrong-model
entries. Catalog tests check required fields, placeholders and registry/navigation
labels in every supported language. These are source and rendering checks, not a
claim of review by native speakers. Worker language updates follow accepted
configuration changes; concurrent operations cannot discard an accepted update.

## Evidence and delivery limits

New [core read evidence](evidence/core-read-2026-10-14.json) and the
[redacted fixture](../tests/fixtures/protocol/studio-pro-fw025-core-read-20261014.hex)
confirm CRC-valid status and firmware 0.2.5 responses from the selected Studio Pro.
The physical retail label was not inspected. The independent
[OS audio observation](evidence/os-audio-2026-10-14.json) records PipeWire output
only. Neither result promotes codec, peer, finder, reset or other candidate bits.
No setting write, candidate packet, reset, unpair or host disconnect was sent.

Packaging records hashes, source revision, dirty status and toolchain, and includes
source, public evidence and documentation. Determinism checks use identical
inputs; they do not establish reproducibility across toolchains. Local development
ZIPs are not published releases. Remote native workflow artifacts and native
Windows/headset results remain outstanding. Official Android-app captures are
required for the advanced protocol work; no Android device was attached locally.
